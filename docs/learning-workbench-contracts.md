# 普通学习流程契约 v1（LW-00）

本契约覆盖普通学习行为及后续设计。自由笔记、位置书签/备注及内部URI已有本地实现，集中搜索与离线完整库备份恢复已有本地实现；实现/验证/人工状态统一见[task](task.md)，当前接口和字段以[API](api-spec.md)、[数据模型](data-model.md)为准。架构取舍见[ADR0012](adr/0012-learning-notes-anchors-and-backup.md)，设计与实施过程归[原任务记录](../dev/README.md)，不在此逐批追加自审或测试计数。

## 1. 范围与一门课程的设计走查

继续使用受管复制资源库，普通流程不依赖题目、作答、Agent、密钥或联网。默认不增加外部目录监听、原地编辑或新依赖。以下使用虚构的“计算机网络”课程做逐步桌面设计走查；这些是待实现行为与验收输入，并非真实窗口/文件执行证据。

## 2. 笔记权威与兼容

**新自由笔记采用普通UTF-8 Markdown资源及已有DocumentWorkfile。** WorkspaceNode仍用kind=resource，原件为创建时的初始MD，当前工作副本为编辑权威；不另建notes正文镜像，不凭“.md”后缀自动编译或发布QuestionFile。笔记ID对外使用resource_item_id，不使用标题、路径或blob hash。树内名称不强制写回MD标题，改名不改变正文hash。

- “新建笔记”是明确创建可编辑文件的意图，可在一次操作内创建初始原件和工作副本，不再要求第二次点击“创建副本”。初始正文为`# 标题\n`；合法文件名1–200字符、固定MD后缀、使用既有Windows名称校验，重名沿用目录自动编号。允许后续保存空MD，遵守现有1MiB UTF-8预算。
- 新建使用持久化request_id收据，同空间同请求同参数返回原节点，不重复创建；不同参数409。数据库提交前失败不得出现可用节点；保留失败字节与收据，重启对账后允许原请求重试。创建返回前回读原件/工作副本hash；不把文件写入与SQLite提交称为原子事务。
- 初始MD固定前置`<!-- studyworkbench-note: {creation_id} -->`及空行，creation_id由服务端分配并随收据持久化，同请求重试复用；正文标题仍为`# 标题\n`。这避免所有空笔记共享同一初始blob，以及复用original_name为TXT的相同字节blob后被旧查看器按TXT分流。不改原有blob元数据，绝不以hash合并逻辑笔记；后续编辑可移除注释，不影响节点身份。
- 已有数据库`notes`保留原ID、富内容JSON、resource_id及revision协议，继续由NoteEditor编辑；既有MD仍走原DocumentPage。汇总列表区分`file_note`与`legacy_note`，仅作读取适配，不后台双写或自动转格式。手工导出MD只能创建独立副本，明确不迁移旧作答note_id关系。
- LW-01提供资源管理器“新建笔记”、文档/媒体页“记笔记”入口；先可新建或打开笔记。来源位置关联由LW-02实现前，UI不得显示“已关联来源”。跨类型统一列表可在LW-04补齐，现有旧笔记入口保持可用。
- 新笔记编辑复用MD draft/draft_base_sha256及layout v2，1MiB预算不变。保存以expected_sha256做冲突校验，使用现有保存收据；409、断连或写失败保留草稿。只有收到保存结果或回读确认当前hash后才清除草稿。关闭脏页确认；布局持久化失败时提示“草稿未落盘”，取消关闭可继续编辑；不承诺进程崩溃前每个按键都已持久化。
- 重启优先恢复已持久化草稿及原base hash，不用当前正文替换base假装无冲突。资源级笔记能力不改标准答案、确认版或旧作答。

LW-01实施触点：Explorer目录/命名与原件留存、DocumentFiles创建/恢复、request_limits、新建UI与PageHost/layout、测试、迁移、API文档。旧NoteEditor/导入/学习事件及export均需兼容回归。

## 3. 位置协议 LearningAnchor v1

位置是普通业务数据，不是系统文件路径或WebView脚本。以下为已实现v1协议，未知版本/类型拒绝写入；读取未知版本显示不支持并保留原始数据。所有ID解析后重新校验workspace归属和墓碑。

公共字段：`version=1`（严格整数）、`workspace_id`、`resource_item_id`、`kind`、`content_sha256`（64位小写hex）。hash由后端从实际文件核对，不能信任客户端自报。kind判别附加字段如下，不允许无关字段混入：

| kind | 位置及版本字段 | 校验/回跳 |
|---|---|---|
| resource | 无位置；content_sha256可null，仅外部link无本地正文时使用 | 打开资源首页；HTTPS链接不承诺远端内容版本 |
| pdf_page | page（严格整数，1起），representation=original | hash为原始PDF；页码≤实际页数及2000页预算 |
| office_pdf_page | page、representation=paginated、preview_id、source_sha256 | content_sha256为派生PDF hash；核对源和产物hash/实际页数，不能以相同页码跨派生版复用 |
| media_time | position_ms（严格非负整数） | hash为媒体原件；≤已验证时长，未知时长不得创建时间锚点，仍可资源级记录；不以字幕/播放器像素定位 |
| text_line | line（严格整数，1起）、line_sha256 | MD/TXT UTF-8原文字节hash为content_sha256；按LF分行，去每行末尾CR后对行UTF-8求line_sha256；空文件视为一空行；不自动归一化其余空白 |

示例（仅协议形状；这些占位ID/hash不是已登记资源）：

```json
{
  "version": 1,
  "workspace_id": "default",
  "resource_item_id": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "kind": "pdf_page",
  "content_sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "page": 12,
  "representation": "original"
}
```

解析结果用状态和说明分开返回：`valid`可定位；`content_changed`hash变化；`missing_content`文件缺失/损坏；`removed`节点墓碑；`out_of_range`页/时间/行越界；`unsupported`版本或格式不支持。跨空间/未知目标直接404，不泄露目标名称。先检查身份/墓碑，再完整性与版本，最后位置；源损坏不回退到另一个同名资源。

内容hash相同且合法位置才显示定位有效。文本行hash即使相同也不在整个文件变化时自动认定有效；可供用户核对并显式重新关联。旧标记保留原anchor，重新关联采用expected_revision并记录旧anchor到修订历史，不伪造原位置仍然有效。派生PDF丢失时可打开原资源并提示，不偷偷重转后跳相同页。

MD首批定位针对原文行；预览可切原文显示目标行，不承诺预览中的像素定位。TXT支持只读原文行导航；Office静态分页绑定对应预览版本，Office结构视图、图片与网页只有资源级位置。文本选区、PDF高亮、图片区域和XLSX单元格另扩版本。

## 4. 书签、备注、笔记关系与删除

`learning_marks`保存服务端分配id、workspace_id、anchor JSON、title（1–240非空字符）、note（0–4000字符）、revision（严格递增整数）、request_id、created_at、updated_at、removed_at；实际字段见数据模型。书签和带备注书签共用一实体，允许同位置多条命名标记，不冒充PDF原生批注。request_id为16–100字符，同空间唯一；同内容创建重试幂等，不同内容409。每条请求≤64KiB。

`learning_mark_revisions`保存每次修改前的标记及关系快照，修改和当前行同事务提交，不允许通过删除清除历史。`learning_mark_notes`保存显式关系：mark_id及判别联合target=`file_note(resource_item_id)`或`legacy_note(note_id)`；两者只能选一，同空间校验，成对唯一。一个mark最多100条关系，关系快照不等于关联笔记全文快照。已有R5事件note_id仍只指向旧notes，不迁移为文件笔记ID；LW-02关系不修改learning_events或旧记录。

从资料“记笔记”可创建资源级/当前位置mark再关联笔记，部分失败如实显示：笔记已创建、来源尚未关联；重试原request_id不复制笔记。直接新建笔记不要求有来源mark。

普通标记列表过滤removed_at，删除需用户确认、expected_revision并只设墓碑。移除资料节点不级联删mark/笔记/关系；集中记录可见“来源已移除”，不自动恢复目录。移除作为笔记的MD节点时正文/工作副本/关系保留，相关入口显示已移除。已有打开编辑器对墓碑的行为沿用现行规则；新的内部链接不绕过墓碑直接打开当前文件。永久擦除/回收站恢复不在本批。

## 5. 内部链接 v1

只在应用内部识别以下已实现URI，不注册Windows协议处理器，不交给网页执行：

```text
studyworkbench://v1/workspaces/{workspace_id}/nodes/{resource_item_id}
studyworkbench://v1/workspaces/{workspace_id}/marks/{mark_id}
studyworkbench://v1/workspaces/{workspace_id}/notes/{legacy_note_id}
```

节点链接打开资源首页；带位置使用mark URI，不把整段anchor/hash塞URL。文件笔记使用nodes，旧富内容笔记使用notes。总长≤2048字符、无userinfo/端口/query/fragment；严格匹配路径段，单次解码后禁止斜线、反斜线、点段、控制字符和额外路径。保留`default`和既有合法ID，不仅允许新UUID而破坏旧ID。无路径猜测、hash匹配或模糊文件名回退。

应用提供复制链接/插入链接和跟随；UI解析URI后调用受鉴权resolve业务API，不按URL直接发任意HTTP。当前空间不匹配时拒绝并提示切换空间，不隐式切换或发跨空间请求；空间归档/目标移除/位置失效显示原因，不绕过授权。解析端每次重验目标与版本，不持久化capability URL。

往返栈仅存应用内目标和视图位置，最多50条/窗口，不存正文或令牌；重新进入目标时再验证。外部HTTPS沿用隔离WebView与导航安全；file/javascript/data等拒绝。导入MD中的内部链接也视为不可信，只能由用户点击；不得自动读取文件或触发模型。旧富内容块v1无任意链接块，不为LW-03放宽题目协议；旧笔记先通过UI“关联来源/打开关联”访问，不宣称已有富内容内联超链接。

## 6. 拟议API、实体与迁移分批

LW-01至04已实现接口和实际字段统一见[API](api-spec.md)，实际实体见[数据模型](data-model.md)。W沿用`/api/workspaces/{workspace_id}`，所有接口继承Bearer/Host/Origin和活动空间校验，拒绝未知字段；服务不得接收客户端磁盘路径。API-01a保留HTTP状态/detail字符串或校验列表形状，新增安全error.code/message/request_id；422列表去输入/未知字段原值，仅给安全定位摘要。关联ID由服务端生成，不与业务幂等编号混同；成功体/媒体Range不换包装，旧调用方仍可读detail。详细兼容及脱敏规则见API，不依据错误元数据自动重放写入。

自由笔记创建遵守第2节的幂等/原件/恢复约束，当前接口和字段以API/数据模型为准，不在本设计文件另行追加每次实施补丁。

marks/revisions/relations已按空间复合外键/唯一约束落表，锚点JSON另做业务校验。后续迁移从实施时实际head追加，不改既有迁移，不提前建立下载、模型或通用任务平台。

集中查找使用SQLite/受管文件做有预算的搜索，不新增搜索引擎依赖；MD/TXT原件不是都属于笔记，搜索范围明确显示“MD笔记、TXT资料、旧笔记及书签备注”。检索活动节点MD当前工作副本/无副本原件、TXT严格UTF-8只读原件全文、旧notes、未删除marks；失效来源mark仍可找到。结构化富内容提取文字/公式/附件说明，不渲染HTML。不得按页只过滤局部数据后谎称已搜全库。

搜索每次最多扫描1000份MD/TXT合计、旧笔记/书签合计10000条，总文字读取预算16MiB、每份MD/TXT≤1MiB；结果按类型及ID稳定排序，响应含truncated与原因/已扫描数量。超过预算明确提示范围不足，不返回“无匹配”冒充全量无结果。每次请求读取版本并重新验证跳转，后续规模要求再引入可重建索引；索引失效不得覆盖正文。坏文件读取字节也占预算，超限最多额外1字节探测；旧笔记按序列化JSON字节预检/计费，避免只计算提取后少量正文。此为当前固定预算，不表示大规模性能验收通过。

TXT结果按Unicode casefold字面匹配，正文首个命中生成临时text_line锚点；LF分行/去行末CR/hash沿已有位置协议。正文命中优先展示正文摘要，名称匹配而正文无匹配则明确仅打开资料，不猜原文行。打开前及文档页定位前重验内容hash，变化后拒绝应用旧行。无新书签/正文镜像/索引/迁移；文件名变更、节点移动沿稳定ID，墓碑和跨空间结果拒绝。

## 7. 完整备份/恢复 v1（LW-05）

首批是**整数据目录学习库**备份与恢复到新空目录，不合并进正在使用的空间。全库范围在UI显式列出所有空间（含归档），用户确认后进行；单空间可移植合并另行设计，不假称全库包是单资源导出v3。备份文件含个人学习信息，默认不加密须提示妥善保管；无自动上传。

备份必须在停止业务写入、停止Office/导入任务并释放数据锁后离线执行；用既有DataLock及SQLite backup机制。重启后中断的任务显式标interrupted，不续读旧机器绝对路径。原子目录切换/启动配置提交可复用data_root.relocate的保护思路，但现有relocate不是已实现备份API。

| 必须纳入并核验 | 说明 |
|---|---|
| SQLite一致快照 | 全部表/迁移版本/触发器/索引，包括归档、墓碑、旧ID、attempt/review/event、任务、全部新增表和完整关系；保留未知字段/版本 |
| 原件及媒体 | 全部受管文件的大小/hash，不重编码；相同blob的逻辑节点分别保留 |
| 工作文件与恢复点 | 当前MD、before/pending、prepared/conflict收据、创建失败字节；不因为失败或孤立就删除 |
| 确认版及附件 | MD/编译内容/材料/标题/资产与不可变确认关系，恢复后旧作答仍能回看当时版本 |
| 笔记、书签和链接 | 旧notes、MD正文、marks修订、note关系与URI稳定ID；不重新分配ID |
| 布局与播放状态 | 数据库layout含已落盘草稿及base hash、文档状态、media playback/subtitle；未落盘内存草稿须先提示保存/保留或取消操作 |
| 派生物/其他学习文件 | 包括Office派生PDF和预览指纹，避免位置锚点因仅缺缓存失效；数据目录中的未知普通文件不静默排除，重解析点拒绝 |

排除进程锁、SQLite的wal/shm/journal文件（已由backup合并提交状态）、WebView profile、业务令牌、媒体capability、R6内存授权、凭据及安装目录/转换组件。若profile存于数据目录，须在LW-05实现时按实际路径列出精确排除清单，禁止凭文件后缀笼统排除学习附件。保留库内既有任务来源路径供本地历史追踪，不自动重用；包不适合作为公开共享证据。

包格式为ZIP64，包含`backup-manifest.json`及`payload/`下的受管相对路径，数据库在payload/study.db。manifest含format=`studyworkbench-backup`、version=1、schema_revision、app_version、created_at（ISO8601 UTC）、files数组中的path/size/sha256、tables按表名映射rows/sha256（按主键排序行摘要）、excluded精确相对路径清单。摘要只校验一致性，不证明包可信或加密；未知格式/较新不支持的schema拒绝激活并保留包。

表摘要使用PRAGMA table_info列顺序、主键优先/其余列确定性排序；逐行紧凑UTF-8 JSON加LF后求SHA256。值以`null`、`integer`（十进制字符串）、`float64`（float.hex）、`text`、`blob`（Base64）标签区分，不把BLOB/空值/数值强转为同一文本。SQLite单值≤64MiB，当前不支持虚拟表；旧schema包先比对原始表摘要，pending内迁移后再按旧列核对原记录不变。未保存MD的草稿与基准hash通过已有layout保留，不自动替换当前文件或提交作答。

WebView运行数据仅按实际保留路径排除：`workspaces/{id}/resource/{tab_id}`、`web/{tab_id}`、`player/{tab_id}`及`workspaces/{id}/link-web`子树；manifest记录实际发现的精确路径。根`.study.lock`、`study.db-wal/shm/journal`不进入payload，WAL已由SQLite backup合并。未知普通文件、失败工作字节和旧备份不凭后缀删除；已中断任务依既有启动恢复标记，不自动续读旧机器路径。

只读包检查、完整离线快照、SQLite语义核对、新空目录恢复及普通UI已有本地实现；人工/发行与实际故障矩阵仍待验。包只含manifest与payload普通文件条目，不额外存目录条目；中央目录≤64MiB，实际条目数在加载ZipFile前核验。路径为NFC、无Windows保留名/非法字符/尾空格或点；拒绝大小写/规范化碰撞及文件与父目录冲突。仅接受Store/Deflate、普通文件和ZIP64大小/偏移扩展；拒绝分卷、加密、特殊文件/重解析声明和未知扩展。只读通过仅证明包结构和列出字节相符，不证明数据库/关系/排除范围完整或来源可信。

恢复步骤：

1. 启动恢复入口选择本地ZIP和新空目录；验证源/目标/安装/配置目录不交叠，目标无已有数据，获取独占锁。此处选择系统文件由普通UI完成，网页/Agent无该权限。
2. 先验证manifest、重复条目、Windows大小写/规范化碰撞、路径越根/绝对/UNC/设备名/ADS、符号链接/重解析点。拒绝未列出payload；未知顶层文件拒绝，不按ZIP名直接解压。
3. 流式解到目标的唯一pending目录，独占创建，不覆盖；按实际解压字节/文件数限制。首批上限100000文件、合计100GiB、单文件8GiB、manifest32MiB；实施前纳入固定可见产品预算。预检可用空间并逐块再查，不仅信任ZIP头/压缩率；超限/空间不足保留失败现场与旧库，提示未激活。
4. 对所有文件大小/hash、SQLite integrity_check/foreign_key_check、表行数/行摘要、工作文件及确认资产关系作校验。缺失/损坏文件或不一致关系使恢复不完整，禁止激活；已有外部冲突按恢复收据显示，不覆写为“已修复”。
5. 若需支持旧schema，先保留包内库副本，在pending内迁移并回归旧行/ID/hash；不支持的未来schema不迁移。激活前再次核验目标目录未被外部写入。
6. 全部通过才将pending安装为目标数据目录、提交外部启动配置；失败保留原配置/原目录，写出可恢复结果。配置提交后重启，临时授权/能力重新申请，不恢复旧会话。最后用普通学习流程逐项验证重启、快照与媒体状态。

备份/恢复进度、取消和错误通过普通本地UI及受控子进程处理，不提供任意路径HTTP接口。设置菜单与启动失败恢复入口均可进入；先保留页面草稿、释放WebView/关闭后端再操作，不持有在线单实例锁调用relocate。所有新增迁移从LW-01起先走已有SQLite备份/事务/旧字节保护；全库产品恢复门槛仍到LW-05/09才可验证。

## 8. 格式等级与后续边界

“当前”是源码能力，不代表实际样本/阶段验收；“目标”是LW计划，不可当现有功能。留存受既有受管添加预算限制。

| 格式 | 当前留存/查看/编辑 | LW-02首批标记目标 | 后续与Agent可读边界 |
|---|---|---|---|
| MD | 留存；原文/受控预览；显式副本可编辑 | 原文行/资源级 | LW-01自由创建；模型正文读取仍未实现 |
| TXT UTF-8 | 留存、只读查看；无通用编辑 | 原文行/资源级 | 多编码/编辑另设计，避免有损替换 |
| JSON | 留存、通用UTF-8只读原文；题目JSON仍用专用严格解析 | 资源级 | 通用查看≤1MiB，严格UTF-8，不自动解析为题库、不执行内容、不开放工作副本编辑 |
| CSV/LOG/VTT/SRT | 留存、UTF-8只读原文≤1MiB | 资源级 | 不执行公式，不推断表格/字幕时间定位；媒体字幕加载仍走独立接口 |
| PDF | 留存、分页/缩放，无原生批注编辑 | 页码/资源级 | 不等于文本选区/OCR，提取预算仍独立 |

| PNG/JPEG | 留存、缩放查看，无图像编辑 | 资源级 | 区域/视觉模型读取另设计 |
| MP4/WebM/M4A | 留存/播放器、续播/倍速/字幕，编码待实际验 | 时间/资源级 | 无模型音视频理解，编码通过逐项记证据 |

| HTTPS网页 | 链接资源、隔离WebView，无本地正文权威 | 资源级 | 无永久远端位置/版本保证，不向网页注入业务桥 |

XLSX使用既有20秒受限查看子进程，无落盘解包或网络读取。源≤16MiB、ZIP≤1024条目/目录256KiB（预检真实数量）、声明解压总量≤32MiB/单部件≤8MiB；读取部件再校验实际大小/CRC。实际读取的XML累计≤100000节点/深度64，拒绝DTD/实体/外部样式；样式与图表正文不读取、不执行，不将其版式呈现为已支持。≤10表/10000单元格/10000共享字符串，单值≤4096字符、结果UTF-8 JSON≤2MiB。超限整体失败并保留原件，不静默截断。关系仅包内且规范化后不越根；宏/活动对象/外部关系拒绝。布局page复用为1起工作表序号，正文/缓存不进入layout；没有独立表格内容镜像或迁移。

LW-07首批采用用户确认有权下载的直接HTTPS媒体文件，只保留原始质量；MP4/WebM/M4A最多512MiB，固定受管路径、队列最多32个待办/单worker。仅443和ASCII域名（路径/query可编码中文），DNS须全部为允许公网IPv4，固定已核地址连接且仍做原域名TLS/SNI校验；最多3次重定向，每跳重验，不用代理/cookies/业务令牌。IPv6/代理、站点提取、登录、DRM、转码、yt-dlp/FFmpeg仍不在首批能力内。复用现有CPython标准库，无新增运行依赖。

新任务须rights_confirmed=true及空间内幂等request_id；暂停/失败保留已存字节，重启不自动联网。resume须实际部分长度/hash、强ETag及206范围一致；已完整落盘且匹配受信进度hash时只校验/入库，不从EOF再请求范围。restart分配新attempt，旧文件保留。完成原件直接由媒体记录引用，同空间相同完整hash的有效媒体复用身份；重复下载副本仍作为任务历史保留，不承诺回收磁盘。目标目录变化时不猜测新目标，保留文件并提示失败。

每次网络I/O10秒期限，固定子进程整体15分钟；取消先关闭父管道，2秒未退出才终止本任务所属进程，处理阻塞DNS。逐块检查实际字节、内容编码/歧义长度/MIME/容器头和磁盘；已知总量按剩余量+16MiB预留，未知总量按512MiB预算。source_url可能含签名query，仅保存在个人库和未加密整库备份；普通列表/错误/日志不携完整URL，不注册Agent下载工具。UI按创建时间倒序、同时间ID升序分页浏览全部下载历史，每页50条并多取1条判断下一页；活动任务状态在原位置更新，不跨页前移。自动刷新保持当前页与首次结果的时间/ID上界；显式刷新、创建成功或重新打开对话框从第一页获取新范围。翻页失败保留原页并可重试，加载中禁止重复翻页，操作后的新结果不被迟到轮询覆盖；目标被移除仍保留下载记录并拒绝打开。分页上界不是事务快照，系统时间回拨使新任务落入旧时间范围时须刷新重新浏览。真实来源/播放验收状态见task。

### 站点提取与质量选择（规划中，未接入产品）

### 授权与人工候选审核

默认授权保持摘要范围，另勾选include_content才可读所选作答正文与当时确认版，预算/到期复核见API；旧版本未知不补造。授权引用不传递权限，所有附件只给元数据。人工录入外部候选默认未验证，审核修订/hash守卫、拒绝保留历史；普通UI单独确认后只新建独立MD，不改标准答案、作答或评分。采用失败保存收据和已建笔记，同参数重试且不覆盖其他编辑。已保存候选属于用户持久内容，撤销临时授权不删除；完整库备份保留候选/修订/采用关系，恢复不恢复grant。模型、凭据与通用资料工具继续规划中。

XLSX字符串执行一次OOXML _xHHHH_解码，保留转义下划线，组合UTF-16代理对并拒绝残缺代理；预算按解码后文本计数，不执行内容。
