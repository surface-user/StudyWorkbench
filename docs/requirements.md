StudyWorkbench 是本地优先的个人学习工作台，交互参考 VSCode。核心对象为工作空间、文件夹、文件/链接资源和学习记录。题库、错题复习、知识点分析、组卷和可选 Agent 是资源与记录之上的能力。408、数学、英语、政治可作为用户自定义分类或模板，不能成为导航和模型的硬编码边界。

## 工作区与打开资源

- 左侧是工作空间及文件夹/文件树，支持定位当前资源；顶部沿用统一编辑器标签；中央根据资源类型打开查看器/编辑器。可选辅助面板承载搜索、学习记录与 AI 助手。
- 文件打开的是具体资源。标签按稳定资源身份去重，移动/改名不改变ID，显示名称和文件哈希不能充当ID。同一文件的编辑/预览可在页内切换。
- 同窗口可打开多个 Markdown、PDF、Word、PPT、图片、网页、视频/音频。计划和统计可作辅助视图；不再依赖“富内容题目/题库与学习计划/导入资料/本地播放器”等互不关联的业务总览来打开每份资料。
- 复用 EditorTabBar/PageHost 的动效、快捷键、状态保留和释放规则。切换保留草稿、位置、网页和播放状态；关闭脏文件确认，失败保留草稿。升级不能丢弃旧标签和草稿。

## 统一添加与查看

统一“添加资源”接收文件、文件夹、本地媒体、网页链接和视频下载请求，按类型分派确定性流程。添加原件与提取题目分开：原件可先作为资料保存，候选题/模型分类须审核后才成为正式题目。

| 资源 | 目标行为 | 当前缺口及验收重点 |
|---|---|---|
| Markdown | 原文编辑、阅读/预览、相对图片与公式 | 目前纯文本导入/块预览，缺独立文件编辑和冲突回写 |
| PDF | 独立阅读、分页/缩放/位置恢复 | 有PDFium提取/页图，缺阅读器；8MiB/20页解析限制不应无说明地作为长期阅读上限 |
| Word | 原件保存；结构预览，按能力提供PDF/HTML派生预览 | DOCX提取不等于分页查看器；.doc与.docx能力分别声明 |
| PPT | 幻灯片预览；必要时派生PDF/图片 | 产品未接入.pptx/.ppt；提取文本不等于渲染，PDF不承诺保留动画/嵌入视频 |
| 图片 | 独立查看、缩放、来源/题目关联 | 复用PNG/JPEG资源读取，更广格式逐项验证 |
| 网页 | 独立WebView、导航、安全失败与浏览器回退 | 复用WebView2隔离，不暴露文件、业务桥或令牌 |
| 视频/音频 | 直接打开某个媒体并恢复位置/倍速/字幕 | 复用媒体服务；当前仅MP4/WebM/M4A入口，编码矩阵待验 |

文件夹导入保留层级、报告重名/重复/失败并可取消。首批建议复制到受管空间，原目录不变；直接附加外部文件夹、自动监听与原地修改另行设计，不能把文件夹导入称为任意磁盘工作区。转换只写可追溯派生文件，禁止覆盖原件；缺能力时明确提示，不悄悄上传云端。

## 题目 Markdown 与学习记录

每题一个UTF-8 Markdown，文件内包含版本化格式标识和稳定题目ID，附件使用可迁移相对引用。普通Markdown环境能阅读题干、公式、图片/图表、选项、答案/解析及来源；本软件校验后渲染为交互题。知识点和原题/变式/原资料关系由ID关联，不按标题猜测。

保留既有单选、多选、填空、计算、证明、主观、阅读题协议能力。缺答案的资料仍可保存/阅读，需要作答时提供待批改路径，不虚构标准答案。未知/损坏格式保留原文件并提示，不能静默丢字段。

Markdown保存内容与相对稳定元数据；SQLite保存索引、确认版本、每次作答/评分修订、错误注记、复习任务和可重建的掌握投影。至少记录题目ID、时间、用户答案/过程、正确性或待批改、错误类型/自评、当时知识点和复习情况，并关联作答时版本。改题/改答案不能重判旧作答，不为记错题不断回写原题。

学习记录可反向打开当前题目MD、作答时版本、相关笔记及原件；资源缺失显示缺失关系，历史保留。

## 可选 Agent

用户可授权指定资料/题目/记录，要求识别候选题、修改确认后保存独立MD、建议知识点与笔记关系、制定练习计划、分析错误与薄弱点、确认后生成变式并记录来源。未确认输出留草稿。

复制/保存、抽样组卷、判分、作答追加与事务由普通程序执行；LLM用于语义识别与建议。无配置、断网或拒绝授权时普通业务正常；远端模型的数据出境另行授权。权限见[agent-design.md](agent-design.md)。

## 数据、发行与实施边界

技术栈继续Flutter/Dart + 固定提交的lightweight_liquid_glass、Python/FastAPI、SQLite/SQLAlchemy/Alembic、Windows WebView2/HTML5。UI不直接访问数据库，普通业务离线，loopback随机端口/令牌与网页隔离不变。

首次使用Windows默认用户数据位置，已有位置/旧库优先保留；失败不静默换空库。安装与数据分离，卸载默认保留数据。新转换依赖先核版本、许可、维护、Windows/冻结/离线体积；本机装有Office不等于干净机可用。

实施顺序：资源管理器（含统一添加基础）→资源标签→文件查看器/编辑器→题目MD协议→记录贯通→Agent。每步先审查兼容性、测试和代码，人工/阶段仍统一待验。**2026-10-26已授权按此顺序继续R1–R6，不以授权表示实现或验收完成。**

详见[架构](architecture.md)、[数据模型](data-model.md)、[审查与转换实证](resource-first-architecture-review.md)、[任务](task.md)。原文保留在[历史快照](archive/resource-direction-baseline-2026-10-25.md)；M0默认启动失败及历史验收遗留不清除。
