# StudyWorkbench — Editor Tab Bar UI 详细设计规范

版本：Tab UI Specification v1.0
目标平台：Windows Desktop
技术栈：Flutter + 现有 Flutter_liquid_glass 组件库
设计参考：VSCode Editor Tabs

## 一、设计目标与不可妥协的原则

StudyWorkbench 的标签栏必须是一套真正的桌面编辑器式分页系统，而不是一组切换功能模式的按钮。

设计目标：

1. 紧凑、扁平、连续，具有明显的桌面软件工作区特征。
2. 活动标签与内容区域具有明确的视觉连接。
3. 新建、关闭、切换标签时顺滑且克制。
4. 标签数量增加时依然整齐，不挤压内容区。
5. 不同页面拥有独立的生命周期和必要的状态保留能力。
6. 保留现有玻璃 UI 的设计语言，但不再让每个标签都成为一张独立的玻璃卡片。

禁止以下设计：

- 大型胶囊按钮式标签。
- 每个标签之间存在明显的大间距。
- 每个标签都使用相同强度的背景模糊、阴影和边框。
- 将所有页面实现成三个固定功能模式。
- 每次切换标签都销毁并重新创建整个页面。
- 为追求动画效果而影响交互响应速度。

## 二、标签栏整体布局

### 2.1 主窗口结构

主窗口保持现有结构：

- 左侧：工作空间与导航。
- 右侧：编辑器工作区。
- 编辑器工作区顶部：标签栏。
- 标签栏下方：当前活动页面。

标签栏只占据主内容区域的顶部，不得覆盖左侧导航。

标签栏与内容区必须在布局上保持连续。活动标签应当像内容区域向上延伸出来的一部分，而不是悬浮在内容区上方的独立卡片。

### 2.2 尺寸规范

以下数值均为 Flutter 逻辑像素，而非物理像素。

| 属性 | 规范 |
|---|---|
| 标签栏高度 | 38 px，允许在 36–40 px 内微调 |
| 单个标签最小宽度 | 112 px |
| 单个标签最大宽度 | 220 px |
| 标签之间的间距 | 0–1 px |
| 标签左侧内边距 | 10–12 px |
| 标签图标尺寸 | 14–16 px |
| 标签标题字号 | 13–14 px |
| 关闭按钮命中区域 | 至少 24 × 24 px |
| 关闭图标尺寸 | 14–16 px |
| 标签顶部圆角 | 4–6 px |
| 标签底部圆角 | 0–2 px |
| 标签栏右侧工具区 | 按实际按钮尺寸布局，不固定占据过宽区域 |

这些尺寸是设计基准，不应为了严格遵守某个数字而破坏实际布局。

### 2.3 标签栏横向排列

标签按照打开顺序从左向右排列。

默认顺序：

`标签 A | 标签 B | 标签 C | 标签 D | +`

要求：

- 标签紧密相邻，不能像当前版本一样每个标签独立悬浮。
- 相邻标签之间使用轻微分隔线或背景明度差异，不使用大间距。
- 新建标签按钮应紧跟可见标签组。
- 关闭按钮不得挤压标签标题，图标与标题应保持稳定的布局。
- 标签标题过长时使用省略号。
- 标签栏不能因为某个标题过长而无限扩展。
- 标签栏必须有明确的宽度约束，不能挤压主内容区。

当标签数量较少时，不要为了填满整行而将每个标签拉伸到很宽。

当标签数量较多时，优先保持标签的可读性，并通过横向滚动和溢出菜单管理标签。

### 2.4 右侧工具区

右侧可以保留少量全局操作，例如：

- 新建标签。
- 恢复最近关闭的标签。
- 标签列表或更多操作菜单。

但是，这些操作不能成为标签栏的视觉主体。

如果标签较少，新建按钮紧跟标签末尾；如果标签过多，则允许标签列表横向滚动，并将工具区保持在固定位置。

不要将加号与标签组之间留出大块空白。

## 三、标签的视觉状态

必须为每个标签定义明确的状态，而不是只通过背景颜色区分。

### 3.1 活动标签 Active

活动标签必须最容易识别。

要求：

- 背景明度略高于非活动标签。
- 背景与下方内容区的背景相协调，形成连续的视觉关系。
- 标题使用主要文本颜色。
- 图标清晰可见。
- 关闭按钮在必要时可见。
- 不使用夸张的阴影、缩放或浮起效果。
- 不要再使用大型、厚重的圆角胶囊形状。

建议采用与当前玻璃背景相协调的轻量半透明表面。活动标签的背景不透明度可以略高于非活动标签，但具体数值应根据现有主题实际测试。

活动标签与内容区之间不应出现一条强烈的分隔线，使两者看起来像两个完全独立的容器。

### 3.2 非活动标签 Inactive

要求：

- 背景透明或仅有很轻的半透明表面。
- 文本与图标使用次级强调程度。
- 不显示明显的阴影。
- 不默认显示高强调的关闭按钮。
- 保留清晰的点击区域。

非活动标签不能完全融入背景，否则用户无法判断哪些页面已经打开。

### 3.3 鼠标悬停 Hover

鼠标悬停时：

- 背景明度轻微变化。
- 关闭按钮出现或提高可见度。
- 图标、文字不发生明显位移。
- 不使用明显的放大、缩小或跳动动画。

悬停状态不能与活动状态混淆。

### 3.4 键盘焦点 Focus

当用户使用键盘切换标签时，必须提供清晰的焦点指示。

焦点指示不能仅依赖鼠标悬停效果，也不能遮挡标题或关闭按钮。

### 3.5 加载状态 Loading

对于需要异步加载的网页或其他页面：

- 标签应立即出现。
- 标签标题先显示可读的默认名称。
- 页面加载过程中可显示轻量的进度指示。
- 加载完成后更新标题。
- 加载失败时显示错误状态，并允许重试。

不要因为网页或后端尚未完成加载而阻塞整个标签栏。

### 3.6 未保存状态 Dirty

对于有未保存内容的页面，例如题目编辑或笔记编辑：

- 提供轻量的未保存状态标记。
- 未保存标记与关闭按钮的显示逻辑不能互相冲突。
- 关闭有未保存内容的标签时，先提示用户保存、放弃或取消关闭。
- 已保存后清除标记。

不能仅依靠关闭按钮判断页面是否需要保存。

## 四、标签内部的布局规范

每个标签的内部结构应保持一致：

`[页面图标] [标题……] [关闭按钮]`

布局规则：

1. 页面图标固定在左侧。
2. 标题占据剩余空间，并使用单行省略。
3. 关闭按钮固定在右侧，不随标题长度变化。
4. 标题与图标之间保持约 6–8 px 间距。
5. 标题与关闭按钮之间保留必要空间。
6. 不允许标题与关闭按钮重叠。
7. 不允许切换活动状态时标签宽度突然变化。
8. 图标、标题和关闭按钮应在垂直方向居中。

页面图标根据页面类型确定，例如：

- 学习首页：Home / Graduation Cap。
- 题库：Book Open。
- 题目：File Question。
- 网页：Globe。
- 播放器：Play / Video。
- 笔记：File Text。

图标应使用现有图标库或项目已有资源，不要为每个页面单独引入一套不一致的图标风格。

## 五、标签宽度与溢出规则

标签宽度不能采用无约束的自适应。

建议以标题长度为基础，在 112–220 px 之间确定宽度。

当标题过长时：

- 保留标题开头的有效信息。
- 使用省略号。
- 完整标题可通过 Tooltip 或标签上下文菜单查看。

当标签数量超出可用宽度时：

1. 标签栏进入横向溢出模式。
2. 不能将所有标签无限压缩到无法阅读。
3. 活动标签在切换时应尽可能自动滚动到可见区域。
4. 横向滚动不能影响标签的点击和关闭操作。
5. 新建按钮和右侧工具区不应被标签挤出窗口。
6. 不允许出现横向滚动条覆盖标签内容的情况。

如果现有组件无法稳定实现这些行为，可以使用 Flutter 自定义 ScrollController 与约束布局实现。

## 六、动画规范

整体动效应接近桌面编辑器，而不是移动端卡片切换。

### 6.1 新建标签

目标时长：140–180 ms。

建议效果：

- 标签轻微淡入。
- 标签宽度平滑展开。
- 相邻标签自然补位。
- 不使用从屏幕外飞入的动画。
- 不使用明显的缩放动画。

新建标签后，活动标签应及时进入可见区域。

### 6.2 关闭标签

目标时长：120–160 ms。

建议效果：

- 标签轻微淡出。
- 宽度逐渐收缩。
- 邻近标签平滑补位。
- 关闭动画期间防止同一标签被重复关闭。
- 关闭完成后更新活动标签和焦点。

如果关闭最后一个标签，应按照页面类型的规则显示默认工作区或空状态，而不是留下异常的空白区域。

### 6.3 切换标签

目标时长：100–140 ms。

建议效果：

- 活动标签的背景和文本状态平滑更新。
- 内容区可以使用轻量淡入淡出。
- 如使用横向位移，位移应极小。
- 不允许整个页面出现明显的左右滑动。
- 不允许切换标签时重新播放视频或重置网页。
- 不允许每次切换都触发完整的页面初始化。

动画必须可中断。用户连续切换标签时，界面应跟随最新的操作，而不是等待之前的动画全部完成。

### 6.4 动画曲线

优先使用轻量、自然的缓动曲线，例如 easeOutCubic。

可以根据实际实现使用：

- AnimatedSize。
- AnimatedSwitcher。
- FadeTransition。
- TweenAnimationBuilder。
- AnimatedContainer。
- 自定义 AnimationController。

但不要求为了使用这些组件而重复包装整个页面。

需要特别注意：AnimatedSwitcher 如果导致页面被重新创建，就不能直接用于要求保留状态的完整页面容器。

## 七、标签的交互规则

### 7.1 单击

单击非活动标签：

- 激活对应标签。
- 显示对应页面。
- 更新活动标签样式。
- 保留其他页面的必要状态。

单击活动标签：

- 不重新创建页面。
- 不重置表单、滚动位置、视频进度或网页状态。

### 7.2 关闭标签

关闭按钮只负责关闭当前标签，不得意外触发标签激活两次。

如果关闭的是活动标签：

- 优先激活其左侧的可用标签。
- 如果左侧不存在，则激活右侧标签。
- 如果没有其他标签，则回到默认工作区或空状态。

如果关闭的是非活动标签：

- 不改变当前活动页面。

关闭操作必须考虑未保存内容和仍在运行的媒体资源。

### 7.3 双击

双击标签栏空白区域可以新建默认工作区标签。

双击标签本身不应执行与关闭、重命名或保存冲突的操作。

如果后续支持标签固定或重命名，需要另外定义规则。

### 7.4 右键菜单

标签右键菜单至少预留以下操作：

- 关闭。
- 关闭其他标签。
- 关闭右侧标签。
- 关闭全部标签。
- 固定标签或取消固定。
- 复制页面地址或资源路径（仅适用于支持的页面类型）。

菜单必须根据页面类型和实际能力显示操作，不得展示没有实现的功能。

对于有未保存内容的页面，批量关闭操作也必须遵守保存确认规则。

### 7.5 键盘快捷键

优先支持：

- Ctrl+Tab：切换到下一个标签。
- Ctrl+Shift+Tab：切换到上一个标签。
- Ctrl+W：关闭当前标签。
- Ctrl+T：新建默认标签。
- Ctrl+1 至 Ctrl+8：切换到对应位置的标签。
- Ctrl+9：切换到最后一个标签。

如果某个页面正在编辑文本，应避免快捷键与输入行为冲突。

快捷键应统一由标签管理层处理，避免不同页面各自注册相互冲突的快捷键。

## 八、页面打开策略

左侧导航打开页面时：

- 如果目标是单例页面，并且该页面已经打开，则激活已有标签。
- 如果目标页面尚未打开，则新建标签。
- 对题目、笔记、媒体等独立资源，应根据资源 ID 区分标签。
- 同一个资源重复打开时，应优先激活已有标签，避免产生大量重复标签。
- 网页标签可以根据产品规则允许不同 URL 对应不同标签。

不能只通过页面显示名称判断两个页面是否相同。

标签身份应由稳定的页面类型和资源标识决定。

## 九、页面状态与资源生命周期

标签栏不能只保存标题和一个当前页面索引。

每个标签至少应有：

- 唯一 ID。
- 页面类型。
- 页面标题。
- 页面资源标识（如果有）。
- 活动状态。
- 页面加载状态。
- 页面自身状态的持有机制。
- 关闭和释放资源的处理逻辑。

状态保留要求：

### 题目页
切换标签时保留作答草稿、选项选择、滚动位置和必要的答题状态。

### 导入页
保留当前文件、导入预览、筛选条件和滚动位置；关闭时根据实际情况清理临时文件或预览资源。

### 网页页
尽可能保留 WebView 实例及其浏览状态。不能因为切换标签就重新加载当前 URL。

### 播放器页
切换标签时不得意外重置播放进度。后台播放、暂停和释放解码资源应由播放器生命周期策略明确控制。

如果无法保留某类页面的完整实例状态，应明确记录限制，不得假装已经实现。

优先考虑 IndexedStack、独立页面状态对象、稳定 Key 或其他适合当前架构的方案。不能简单地将所有页面都放进一个无限增长且永不释放资源的容器。

## 十、Flutter 实现要求

在开始修改前，检查当前项目中的：

- TabManager 或等价的标签状态管理组件。
- 页面路由与页面工厂。
- Flutter_liquid_glass 的现有主题与组件。
- 页面缓存和状态恢复机制。
- 网页与播放器的资源生命周期。
- 当前窗口尺寸和布局约束。

优先修改现有架构，不要为了实现视觉效果而重写所有业务页面。

建议将标签栏拆分为可独立维护的组件，例如：

- EditorTabBar：标签列表和布局。
- EditorTabItem：单个标签及其视觉状态。
- EditorTabActions：新建、恢复和更多操作。
- TabManager：标签状态、激活、关闭、去重和快捷键。
- PageHost：根据活动标签展示对应页面并管理生命周期。

以上为建议的职责划分。如果项目已有等价组件，应复用现有实现，不必机械地创建同名文件。

## 十一、验收测试

必须实际测试以下场景：

1. 连续打开至少 5 个不同类型的标签。
2. 新建标签时，标签平滑出现，邻近标签布局正常。
3. 连续快速切换标签时，不发生闪烁、卡顿或状态丢失。
4. 关闭中间标签时，两侧标签平滑补位。
5. 关闭最后一个标签时，应用正常回到默认工作区。
6. 标签标题很长时能够正常省略。
7. 标签数量超出窗口宽度时，溢出和滚动行为正常。
8. 窗口缩放后标签栏布局正常。
9. 题目页切换回来后，作答草稿仍然存在。
10. 网页切换回来后，不会无故重新加载。
11. 播放器切换回来后，播放进度不会无故重置。
12. 关闭未保存的页面时，会执行正确的确认逻辑。
13. 键盘快捷键能够正常工作。
14. 后端不可用时，标签栏依然可交互，并正确显示页面错误状态。

## 十二、交付要求

完成后请提供：

1. 实际运行截图，展示至少 5 个标签。
2. 活动、非活动、悬停和加载状态的截图或说明。
3. 新建、关闭、切换标签的实际运行效果。
4. 修改涉及的核心组件与文件。
5. 状态保留的实际测试结果。
6. 自动化测试结果。
7. 尚未实现的行为和技术限制。

不要只提供静态设计图或通过测试的口头说明。

最终验收标准是：用户在 StudyWorkbench 中打开多个题目、网页、视频和资料时，能够感受到统一、紧凑、自然的 VSCode 式工作区分页体验，同时不会因为切换标签而丢失学习进度。
