# 单作品的站点双轨选择确认

用户在同一 B 站预览内从已列出的轨道各选一条视频、一条音频，再显式确认处理权利。后端重新读取作品元数据，校验作品、站点下载许可、轨道身份、媒体资源路径和质量声明。确认结果可在该预览的有效期内查询。交互顺序沿用项目的预览、选轨、确认契约，[Seal](https://github.com/JunkFood02/Seal) 仅作产品交互参考。

稳定引用与临时列表索引无关。作品或逻辑轨道改变、同一身份有多个匹配项、特殊请求头、合计声明大小越界等情况会阻止选择。临时签名查询串变化后可以核对同一选择，媒体域或路径变化需要重新预览。DASH 轨道在元数据提取完成后仅保留资源指纹；输出不含媒体地址或请求头。

## 验证

- Python 3.12.7、3.13.17 分别运行 `pytest -q`，覆盖站点提取、预览、双轨选择、单文件确认、下载 HTTP 及队列。两套环境各 219 项通过，退出 0。其中 17 项新增用例覆盖同一预览选择、顺序和签名变化、重复/越空间请求、轨道歧义与漂移，以及确认期间取消和过期。首次编写正向用例时误把连接关闭列表当作请求明细，修正测试观察位置后重跑。
- 查询与确认经应用 HTTP 接口运行。正向用例用自制页面和 API 响应提供两档视频及一条音轨，实际运行提取与业务逻辑。预览和复核分别产生三次元数据请求，重放相同确认返回原收据。未产生媒体请求、下载任务或媒体记录。
- `packaging/windows/build-backend.ps1` 退出 0，61 个冻结应用模块与源码一致。分别启动源码及打包后的 Windows 后端，真实回环 HTTP 核实不存在的预览返回 404，未同意处理权利返回 422。错误响应沿用应用统一的参数脱敏。打包后端仅验证这两个拒绝路径。
- `ruff check backend tools` 与 `git diff --check` 退出 0。

## 范围

本次确认只选择轨道，十分钟预览到期、取消或重启后失效。单文件下载沿用已有入口。双轨结果保持 `download_supported=false`；实际下载需要独立实现同一任务的两轨传输、持久来源及尝试记录、共享预算、实际轨道探测和原子合成入库。此次仅使用自制响应，线上站点仍待验证。审查和人工测试依本轮安排暂缓。
