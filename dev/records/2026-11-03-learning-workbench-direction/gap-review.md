# 当前实现与预期学习工作台的差异评估

日期：2026-11-03

状态：**待讨论、待判断是否采纳；不是已批准的需求、架构变更或开发任务。**

本文依据本次对话中用户明确表达的产品预期、现行 docs 文档及本地源码编写。按用户指定保存在 `doc/`；当前有效规范仍在 `docs/`，本文不取代它们。不因这份评估重排 R1–R6、改变技术栈、取消既有验收或扩大 Agent 权限。

## 1. 用户现在希望得到什么

软件面向各类学习者，不限定程序员、特定考试人群或只做题的用户。

用户可以在学习空间中保存、组织和查看自己的学习资料，包括但不限于 DOCX、PPT/PPTX、XLS/XLSX、Markdown、TXT、JSON、图片和视频；希望提供视频获取到本地的下载能力。学习中能自行添加书签、备注和超链接，方便继续阅读、回看和联系相关资料。

即使没有 Agent，软件也应能独立作为学习笔记和资料工作台使用。在此基础上，Agent 可帮助分析题目，也可逐步扩展到其他学习活动；具体新增能力尚未确定。

需要保留两点区别：

- 用户把“查看各种资料、笔记、媒体、视频下载”等视为产品基础价值，不表示它们已经实现，或每项都适合在同一批开发。
- “保存文件”“内置查看”“编辑”“理解内容并交给 Agent”是不同能力，不能只因导入成功就声称全部支持。

**本文的产品理解：一个能独立支持资料阅读、媒体学习和笔记整理，并允许 Agent 在用户授权范围内参与的本地学习工作台。** 这句话是对用户预期的整理，不是竞争优势已经得到验证的结论。

## 2. 总体判断

现行需求已经明确“以文件与学习资源为核心”，也明确题库、复习、统计和可选 Agent 建立在资源之上。因此，用户的新描述与已有资源中心方向总体一致，无需据此认定已有 R1–R5 都走错了。

当前实现的成熟度分布存在偏重：资源管理基础、题目确认版本、作答与批改历史已有较多实现；围绕任意资料的自由笔记、位置备注、书签、内部超链接和统一回找仍不足。用户想要的普通阅读与记录体验，还不能仅靠现有题目/作答记录功能覆盖。

主要差异有三类：

1. **已有基础但覆盖受限**：文件查看、媒体播放、笔记编辑、位置恢复。
2. **缺少完整的日常学习流程**：自由新建笔记、给资料某个位置做备注、多个书签、跨资料跳转、搜索这些记录。
3. **明确尚未完成的能力**：表格查看、视频下载、模型及凭据接入、广泛资料上下文的 Agent。

这些差异值得评估，但它们本身不构成“立即全量改造”的依据。

## 3. 逐项差异

| 用户预期 | 当前本地实现与限制 | 差异及后续待判断事项 |
|---|---|---|
| 面向各类学习者 | 工作空间与分类不硬编码为特定科目；学习页、拆题和历史记录仍占较大功能比重 | 产品方向兼容；需评估不刷题用户能否顺畅完成资料阅读与记录，是否需要调整默认入口 |
| 自由保存学习文件 | 已有受管复制、文件夹/链接、搜索、改名移动及树节点移除；未知格式可保留并提示限制 | 不能把受管逻辑树当成任意系统目录原地工作区；需明确用户是否期待外部修改同步 |
| 查看 Markdown 和 TXT | MD 可阅读、预览并显式建立工作副本编辑；UTF-8 TXT 已有只读查看 | TXT 不应列为完全未支持；通用 TXT 编辑、多编码支持仍需另行设计 |
| 查看 JSON、代码等文本资料 | 有严格题目 JSON 导入；通用查看器只对 MD/TXT 等显式分流 | 题目 JSON 导入不等于通用 JSON 阅读/编辑，尚无 VS Code 式代码工作区能力；用户是否需要代码编辑功能仍应与学习用途分开判断 |
| 查看 DOCX | 已有受限结构预览；可选离线组件可生成派生 PDF | 不保证与 Word 完全相同的版式、交互或编辑能力；复杂字体、公式和第三方资料仍需验证 |
| 查看 PPT/PPTX | PPTX 可由可选离线组件生成静态派生 PDF；旧 PPT 未支持内置预览 | 静态分页不等于 PowerPoint 播放，不保留动画或嵌入视频；需分别确定 PPTX、旧 PPT 的目标支持等级 |
| 查看 XLS/XLSX | 未发现独立表格查看器及其产品入口 | Office 安全解析中允许受限内嵌 XLSX 图表数据，不等于支持独立 XLSX；应先确定只读、公式结果、多工作表和编辑范围 |
| 查看 PDF、图片 | PDF 分页/缩放/位置状态、PNG/JPEG 查看已有实现 | 文件阅读不等于有 PDF 文本选区、高亮、原生批注或任意图片格式支持 |
| 保存和观看视频 | 已有 MP4/WebM/M4A 本地导入、播放器、续播、倍速和 WebVTT 字幕 | 受容器、编码与大小预算限制；还缺视频时间点书签/笔记；后缀通过不代表所有编码可播放 |
| 获取视频到本地 | 视频下载队列、质量选择、取消/重试/恢复等仍在未完成项中 | 当前本地媒体导入不是下载功能；来源范围、队列、组件、存储和失败恢复均需设计 |
| 不依赖 Agent 也能当学习笔记 | MD 工作副本编辑、导入产生的笔记编辑、图片/附件引用等已有基础 | 尚未形成统一、低门槛的自由新建笔记与资料旁记流程；不能把“可编辑已有笔记”当成完整笔记产品 |
| 自行添加书签 | 有文档阅读位置状态和媒体续播位置 | 一个“上次位置”不等于用户可命名、分类、搜索的多个书签；未发现统一书签模型/接口/入口 |
| 给资料内容做备注 | 有围绕作答追加的 annotation/reviewed 事件、错因、自评和笔记关系 | 作答注记不等于 PDF 某页、文本某段、视频某时刻的备注；通用资源位置批注尚未形成 |
| 添加超链接 | 已有独立 HTTPS 网页链接资源、相对图片和部分资源关系 | MD 预览点击链接目前提示地址；尚无统一的“资料→页码/时间点→备注/笔记”内部跳转体验，不能把这些已有关系一概说成全部没有 |
| 找回学习痕迹 | 已有同空间资源名称搜索、题目/历史等专门入口 | 尚未形成覆盖笔记正文、备注、书签和资料内容的统一检索与结果跳转；全文搜索/OCR能力须分开验证 |
| Agent 分析题目及其他学习内容 | R6 首批只有本地授权、所选作答摘要读取与 UI；无模型、凭据、远端出口或广泛资料正文读取 | 当前不能提供语义分析。既有设计有资料识题、关联、计划、分析和变式方向，但通用学习助手范围仍需判断 |
| 长期可靠地保存资料与学习记录 | 原件保留、受控保存、确认快照及追加历史已有保护；资源导出存在 | 现有导出不是完整学习库恢复包；若继续增加书签/备注/关系，备份恢复应一并纳入，避免“文件还在，学习记录丢失” |

以上“未发现”是对本次所检查源码、模型、路由与入口的结论，不是对所有历史分支、外部工具或未来插件能力的断言。“已实现”也不等于发行、普通用户、干净机和阶段验收通过。

## 4. 最需要判断的产品问题

### 4.1 文件管理器承担多大的责任

当前方案是复制资料进入受管数据目录，树内稳定 ID 与原件 blob 分离。它能保留学习上下文，也会让用户产生“原文件变了，这里为什么没同步”的疑问。

待判断：继续以受管资料库为主，还是增加外部目录原地工作区？前者仍需做好导入、导出和说明；后者会引入监听、冲突、权限与外部删除处理，属于重要架构议题，不能顺便实现。

### 4.2 每种格式支持到什么程度

建议讨论时逐种格式分别标明：

| 支持等级 | 含义 |
|---|---|
| 留存 | 保存原件、可管理和导出，但可能不能内部显示 |
| 查看 | 能受控展示内容，明确结构预览/静态分页/原生播放等方式 |
| 学习标注 | 能添加书签、备注，并返回原位置 |
| 编辑 | 能修改内容，具备保存、冲突与恢复规则 |
| Agent 可读 | 经授权提取限定内容，可说明引用来源与提取限制 |

用户说的“所有学习文件”可以作为覆盖目标，不宜直接变成“所有格式无损查看和编辑”的承诺。哪些格式值得优先支持，应由实际学习资料决定。

### 4.3 自由笔记与资料旁记的关系

待判断：用户主要需要独立的长篇笔记、针对资料某个位置的短备注，还是两者都需要？是否希望笔记本身也是可携带的普通 MD？目前已有数据库笔记和 MD 工作副本，不能在未决定权威关系时再引入第三套相互割裂的数据。

一种待评估的最小体验是：从任意资料打开“记笔记”，允许新建或关联已有笔记；记录来源位置；回看笔记时能跳回资料。不要求先拆题、作答或配置模型。

### 4.4 位置与超链接如何长期有效

建议评估资源稳定 ID 与位置描述的组合：PDF 页、视频时间点、文本段落/选区等。只记录文件名或磁盘绝对路径，遇到改名移动容易失效；只记录像素坐标，也难以应对缩放和重新排版。

还应判断内容更新后的行为：旧备注继续指向原版本、提示位置过期，还是允许用户重新关联？不能把旧笔记悄悄指到新内容。具体模型、协议与迁移需后续设计，本文不预先命名已有接口。

### 4.5 视频获取能力的边界

待判断：支持哪些可下载来源、仅直接媒体链接还是站点提取、下载后如何选择目标空间/目录、如何显示失败与重试、如何处理大文件和磁盘不足。转码、字幕下载、登录、DRM等必须单列，不能由一个“下载视频”按钮隐含承诺。

应先确定用户有权获取的来源及必要组件，再按项目约束审查固定版本、许可证和 Windows 支持。本文不引入依赖或启动下载任务。

### 4.6 Agent 如何参与普通学习

题目分析可以保留，同时评估资料解释、根据指定文档整理提纲、结合用户备注回答疑问、比较两份资料等候选场景。这些仅是助手建议，用户尚未逐项确认，不应全部排进实施任务。

Agent 应复用用户自己的资料、笔记、书签和备注，输出可回查依据；范围授权、远端传输说明、来源验证和采用确认继续有效。未接入模型时，普通学习流程仍可独立完成。

## 5. 如果采纳方向，建议的推进顺序

以下是候选顺序，不是对现有 task.md 的替换，也不表示立即暂停 R6。应由用户先判断，再进入需求、设计和任务拆分。

1. **先验证无 Agent 的最小学习流程。** 选一门真实课程的 PDF/课件/视频和笔记，确认“导入→阅读/播放→新建笔记→加书签/备注→退出重开→回到原位置”是否值得长期使用。
2. **优先补记录与回找。** 自由笔记、位置书签/备注、内部链接与失效提示、集中浏览/搜索；同时考虑数据备份，不只扩大文件后缀。
3. **按真实资料补格式。** 给 XLS/XLSX、旧 Office、通用文本等确定优先级及支持等级，采用真实复杂样本验收；不做完整 Office 或代码 IDE 的默认承诺。
4. **把视频下载作为独立基础任务。** 与本地播放区分，完成来源、组件、队列和故障恢复设计；如果用户认为下载是首要场景，可以与第二步调整顺序。
5. **接入已确认的 Agent 场景。** 依赖范围明确的资料读取、引用和人工采用，不让基础学习能力依赖模型。

可继续复用已有资源身份、标签和草稿保留、原件保护、文档预览、媒体状态、笔记编辑及题目版本/作答历史。题目相关实现可以作为学习工作台中的专门能力保留，不需要因调整重心而删除旧数据或推翻保护规则。

## 6. 用什么场景判断方向是否值得采纳

| 判断场景 | 建议观察的结果；不是现有通过结论 |
|---|---|
| 完全不用 Agent、不做题地学习一门课 | 能完成导入、阅读、记笔记和再次回看，操作不依赖题目/作答入口 |
| 在 PDF 第 12 页与视频某个时间点做记录 | 重启后仍可找到并返回位置，缩放不破坏关联 |
| 资料改名或在树中移动 | 原有书签、备注和内部链接继续指向同一资源 |
| 资料内容或派生版本变化 | 明确显示位置/版本是否仍有效，不静默关联错误内容 |
| 搜索自己的疑问或书签标题 | 能找到对应记录和来源；若不支持资料全文/OCR，应明确区分 |
| 下载视频被中断或磁盘不足 | 状态、重试和已完成文件可解释，不伪装成功、不覆盖个人资料 |
| 迁移或恢复学习空间 | 资料、笔记、书签、备注、关系和学习历史一起校验；失败可恢复 |
| 按需调用 Agent | 只使用授权集合，输出有依据，用户拒绝采用不影响原件和正常学习 |

评估应同时记录用户完成任务需要多少整理、是否需要频繁切换外部应用、重启后是否容易继续、是否能找回过去的疑问。本文不先设未经讨论的效率提升数字。
