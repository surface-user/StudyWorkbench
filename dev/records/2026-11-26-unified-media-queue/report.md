# DL-03h 站点单文件下载和本地双轨合成

将[本地合成 #113](https://github.com/surface-user/StudyWorkbench/pull/113)和[备份版本校验 #120](https://github.com/surface-user/StudyWorkbench/pull/120)接到[站点下载 #128](https://github.com/surface-user/StudyWorkbench/pull/128)使用的 0022 后端。两份实现原先分别修改了同一队列的任务展示、启动和重试入口。现按来源选择工作进程，共用容量限制和同空间请求 ID。站点临时媒体地址只传入已确认任务的下载进程，本地合成只接收已核对的本地媒体选择。

| 验证 | 结果 |
| --- | --- |
| 站点确认、格式预览、直链、本地合成、来源、启动和备份的 pytest 专项 | Python 3.12 和 3.13 各 242 项通过，退出 0。首次运行既有 Windows 目录连接测试时权限不足，保留失败记录，使用具备该权限的隔离目录复测 |
| `packaging/windows/build-backend.ps1` | 锁定环境 70 个包版本一致，59 个冻结业务模块与源码一致，退出 0 |
| `tools/check_media_mux.py` | 源码和 Windows 程序各通过 10 个实际 FFmpeg 场景，包含中断、重启及完整备份恢复 |
| 同一 0022 资料库中的两种任务 | 项目自制音视频的站点确认和本机 HTTP 传输成功。把完整资料库还原后，Windows 程序通过普通资料复制导入两条轨道，调用固定 FFmpeg 合成并入库。跨来源复用请求 ID 返回 409。再次整库备份还原，两份原始请求各自返回原任务，数据库完整性检查通过 |

早期混合测试读取了一份只留数据库的旧测试目录，备份正确拒绝缺少的 MP4。重建并保留完整测试目录后通过。真实站点的网络条件另由站点任务跟踪，以上媒体均来自项目自制样本。
