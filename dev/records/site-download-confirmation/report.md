## 单文件确认与传输

固定版本 `bilibili-preview-v3` 在用户选择原格式并再次确认后，重新提取同一作品。当前接受普通单 P、自报允许下载、大小及质量明确、原域和完整地址一致的 UPOS 单文件 MP4。确认收据随原下载队列一起持久化，签名地址仅保存在当前执行内存。排队过期或服务重启须重新预览，原确认重试可取得同一任务。入库前核验声明大小、实际哈希及 MP4 的 H.264 视频和 AAC 音轨。接口与失败状态见 [API 契约](../../../docs/api-spec.md#站点单文件下载确认)。

## 元数据与传输的共用额度

源自站点双轨交接的依赖核对。原单文件确认重新获取页面与格式后，媒体工作进程会重新开始请求次数和字节计数。现在固定提取进程报告本次实际消耗；确认入队前要求已知的媒体字节能放入剩余额度且仍有请求可用。媒体工作进程按实际请求、重定向与读取字节扣减额度，父进程在排队、校验、入库前继续检查同一运行时限。用量只在进程间传递。普通预览响应、既有数据库和库备份不增加字段。

- 在 #131 基线上用自制来源重放 5 组缺失、无效或已用完的计数，旧接口均返回 200。测试拦截调度，未发出媒体请求；回归测试原始退出码为 1。修复后同组均返回 409，未新增下载行。
- 两种锁定 Python 分别运行 `python -m pytest -q`，范围为站点确认、预览/探针、媒体 HTTP、直链队列和本地合流，共 235 项各通过，退出码 0。新用例同时核实共享对象用于连续两个 HTTP 传输时不会重置额度、最后一次请求遇重定向不会继续解析域名、过期的文件不会发布。
- 以项目自有 2,177 字节 H.264/AAC 样片运行已有 API 端到端测试。独立下载工作进程从本机测试 HTTP 服务读取实际字节，随后入库、备份、恢复并复用确认，退出码 0。
- Windows 打包后 59 个应用模块逐项匹配源代码。实际冻结下载工作进程分别拒绝用尽的请求、字节与时限，均未创建目标文件。源码及冻结产品验证真实授权样本仍在允许公网 IPv4 检查处停止，两者的格式、下载任务和媒体记录数均为 0。
- 双轨来源仍需明确选择同一作品的一条视频和一条音频，持久绑定两项来源及共同运行收据，再交给既有 FFmpeg 执行。使用锁定 FFmpeg 在本机将自有样片拆成带 moov/moof/mdat 的视频 1,598 字节、音频 1,052 字节，两条分片 MP4 均被当前结构预检以 422 拒绝。这项结果属于自制样本；用户真实作品尚未取得播放格式。
